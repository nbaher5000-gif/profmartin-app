# اپ پروفسور مارتین (Expo / React Native)

پروژه پایه اپ موبایل برند Professor Martin — کاتالوگ، سبد خرید، پرداخت (شبیه‌سازی‌شده)، پروفایل.

## اجرا

```bash
npm install
npx expo start
```

سپس با اپ **Expo Go** (اندروید/iOS) کد QR را اسکن کنید، یا از شبیه‌ساز استفاده کنید:

```bash
npm run ios      # نیاز به macOS و Xcode
npm run android  # نیاز به Android Studio
```

## اجرا روی وب

```bash
npm install
npm run web
```

این دستور اپ را با `react-native-web` در مرورگر باز می‌کند (پورت پیش‌فرض معمولاً 8081 یا 19006).

برای گرفتن خروجی build نهایی (استاتیک، برای هاست کردن روی هر سرویسی مثل Netlify/Vercel):

```bash
npx expo export -p web
```

خروجی در پوشه `dist/` قرار می‌گیرد.

### نکاتی درباره نسخه وب

- تب **«سایت»** روی موبایل از `react-native-webview` استفاده می‌کند، اما چون این کتابخانه از پلتفرم وب پشتیبانی نمی‌کند، در `WebsiteScreen.js` یک مسیر جداگانه برای وب نوشته شده که همان صفحه را با `<iframe>` نشان می‌دهد.
- راست‌چین بودن صفحه در نسخه وب از طریق `public/index.html` (با `dir="rtl"` و `lang="fa"`) تضمین شده؛ این فایل، قالب HTML پیش‌فرض Expo برای build وب را بازنویسی می‌کند.

## ساختار پروژه

```
App.js                        نقطه ورود، تنظیم RTL و Provider سبد خرید
src/
  data/products.js            رنگ‌ها، دسته‌بندی نیاز پا، محصولات نمونه
  context/CartContext.js      مدیریت state سبد خرید و سفارش‌ها
  navigation/RootNavigator.js تب‌های پایین + استک ناوبری
  screens/                    ۶ صفحه: خانه، کاتالوگ، جزئیات محصول، سبد خرید، پرداخت، پروفایل
```

## آنچه هنوز mock است (باید قبل از انتشار واقعی جایگزین شود)

| بخش | وضعیت فعلی | باید تبدیل شود به |
|---|---|---|
| محصولات | آرایه ثابت در `products.js` | fetch از API واقعی/دیتابیس |
| پرداخت | شبیه‌سازی OTP بدون پیامک واقعی | اتصال به درگاه (زرین‌پال و...) + سرویس پیامک |
| سفارش‌ها | ذخیره در state حافظه (با بستن اپ پاک می‌شود) | ثبت در بک‌اند/CRM فعلی برند |
| ورود کاربر | بدون احراز هویت واقعی | OTP واقعی + ذخیره token با `expo-secure-store` |
| دکمه واتساپ | فقط ظاهری | لینک واقعی با `Linking.openURL("whatsapp://send?phone=...")` |

## اتصال به بک‌اند فعلی (n8n / server.js)

پیشنهاد می‌شود یک لایه API ساده (REST) روی همان سرور Node.js موجود اضافه شود که این صفحات را serve کند:
- `GET /api/products` — لیست محصولات
- `POST /api/orders` — ثبت سفارش (که می‌تواند همان webhook یا منطق n8n را صدا بزند تا در CRM هم ثبت شود)
- `POST /api/otp/send` و `POST /api/otp/verify` — احراز هویت شماره موبایل

با این کار، هم اپ موبایل و هم ربات واتساپ از یک منبع داده و یک CRM مشترک استفاده می‌کنند.
